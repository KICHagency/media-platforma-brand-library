# Проверка результата

Для каждого файла записать pass/fail и конкретный дефект. Любой критический fail блокирует передачу ассета как готового.

## Обязательные проверки

- [ ] Изображение соответствует сюжету, возрасту, действию и устройству.
- [ ] Зелёный свет заметен на плоскости лица, не только по контуру.
- [ ] Другая часть кожи сохраняет естественный цвет; нет общего зелёного фильтра.
- [ ] Нет восковой ретуши, искусственно усиленных пор, морщин и перешарпа.
- [ ] Волосы выглядят отдельными волосками/прядями, без волнистой нейромассы.
- [ ] Глаза, зубы и выражение лица правдоподобны.
- [ ] Пальцы анатомически верны, хват и контакт с устройством убедительны.
- [ ] Экран, клавиатура, шарнир и ориентация устройства согласованы.
- [ ] В исходнике не потеряны макушка, кисти и значимые части устройства.
- [ ] Нет случайных надписей, логотипов и водяных знаков.
- [ ] Для cutout есть alpha; нет впечённой шахматки, фона и цветной каймы.
- [ ] Фактические размеры подходят для макета; изображение не растянуто.
- [ ] В макете не закрыты текст, лица и ключевые действия; обрез намеренный.
- [ ] Знак, паттерн и текст остаются редактируемыми слоями.
- [ ] В серии есть разнообразие людей, одежды, устройств и поз.
- [ ] Сохранены промпт, версия и ссылка на финальный файл/слой.

## Как проверять

Сначала полный кадр, затем 100%: лицо, волосы, обе руки, устройство, края alpha. После этого — реальный размер в макете. Alpha проверить на двух контрастных подложках и по наличию прозрачных пикселей; один RGBA-режим ещё не доказывает прозрачность. Техническая проверка не заменяет визуальную.

## Запись проверки

`asset_id`, `review_date`, `reviewer`, `status`, `defects`, `correction`, `final_figma_url`. Общую фразу «серия проверена» не использовать вместо фиксации проблемных файлов.
