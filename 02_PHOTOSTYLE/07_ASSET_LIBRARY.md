# Библиотека ассетов и GitHub

Пакет можно положить в папку `Photo/` общего репозитория Media Platforma. В корневом README добавить ссылку на Photo/README.md, а в общих инструкциях — указание читать Photo/AGENTS.md для задач с фото. Не заменять им инструкции по Metal 3D.

## Файлы

Рекомендуемые папки: `assets/environment/`, `assets/hero/`, `assets/cutouts/`, `references/`. Добавьте их при экспорте PNG из Figma; сейчас архив содержит документацию и каталог ссылок.

Имя: `mp-photo-001-environment-v01.png`, `mp-photo-011-hero-v01.png`. Новая правка получает v02. Утверждённый файл не перезаписывать без истории версии.

## Экспорт

Для прозрачного ассета экспортировать сам слой фотографии, не композицию с фоном. Для цельного кадра экспортировать слой фото. Композицию со знаком или группой хранить отдельным превью. Проверить прозрачность, разрешение и отсутствие лишней рамки после экспорта. Не увеличивать маленький исходник только ради формального размера.

## Каталог

В `examples/asset_catalog.json` уже есть 30 asset_id, режим, подпись, ссылки на исходный слой и композицию. Локальные пути отсутствуют до экспорта, это обозначено null. Дополните `asset_path` после загрузки файлов; не оставляйте ссылки на временные URL или локальные диски автора.

Храните отдельно статус референса и результат проверки. «Принят как направление» не равен «каждый пиксель проверен». При публикации добавьте владельца, условия использования изображений и дату обновления; не назначайте автоматически открытую лицензию бренду.

## Проверка готовности репозитория

- Все относительные ссылки открываются.
- JSON читаются стандартным парсером.
- Примеры содержат полный набор правил и один режим камеры.
- PNG доступны, если обещана автономная библиотека ассетов.
- Figma-ссылки доступны адресату; приватная ссылка сама по себе не даёт права доступа.
- В каталоге нет секретов, временных URL, путей scratch и отвергнутых вариантов.

Этот пакет подготовлен для размещения, но сам по себе не создаёт репозиторий и не публикует файлы.
