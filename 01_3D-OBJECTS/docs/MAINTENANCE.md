# Поддержка библиотеки и подготовка GitHub

## Структура

Корень содержит README.md и AGENTS.md как точки входа, оба JSON и каталоги. `assets/` — готовые PNG, `references/` — эталон, `docs/` — инструкции, `examples/` — шаблоны задания и проверки. Сохраните эту структуру при переносе: относительные ссылки и пути в JSON рассчитаны на неё.

## Добавление объекта

1. Создайте изображение по GENERATION.md и проведите QUALITY.md.
2. Сохраните PNG под устойчивым именем, например `31-bell.png`. Не переименовывайте существующие файлы без обновления ссылок.
3. Добавьте запись в catalog.json: уникальный id, name, file, width, height, mode, фактическая доля полностью прозрачных пикселей, SHA-256. Ссылку figma добавляйте только после размещения, иначе оставьте null.
4. Обновите CATALOG.md. Сохраните использованный бриф и review в папке соответствующего нового выпуска, если ведёте историю генераций.
5. Запишите изменение в CHANGELOG.md. При изменении правил материала или света обновите версию стандарта и соответствующие промпты.

Новый файл с тем же именем должен сопровождаться новой контрольной суммой. Техническая доля прозрачных пикселей помогает проверять файл, но не является оценкой качества изображения.

## Изменение правил

Текущая версия визуальных правил — 2.0. Версия этой документации — 1.1. Версии отделены намеренно: оформление документации не означает изменения визуального стиля.

Обновляйте STYLE.md, основной JSON, негативный JSON, QUALITY.md и слайды Figma согласованно. Не меняйте один документ молча. В случае расхождения сначала зафиксируйте его; не выбирайте удобный источник без проверки текущего задания владельца.

## Подготовка репозитория

Распакуйте архив и загрузите **содержимое** папки `media-platforma-metal3d` в корень будущего репозитория. Нужны реальные PNG и документы, а не один ZIP. Проверьте относительные ссылки, 30 записей каталога и наличие исходного конуса. После публикации внесите фактический URL репозитория в README при необходимости.

Публичность репозитория и условия использования определяет владелец. В этом пакете нет придуманной открытой лицензии: публичное размещение само по себе не задаёт права на свободное использование. Не добавляйте MIT или другую лицензию автоматически.

После загрузки протестируйте типовую задачу: дайте другому ИИ README и попросите создать новый предмет, отсутствующий в каталоге. Проверьте, прочитал ли он документы, действительно ли увидел изображения, сохранил ли прозрачность и выполнил ли приёмку. Такой тест показывает работоспособность процесса конкретной системы; он не заменяет визуальный контроль.
