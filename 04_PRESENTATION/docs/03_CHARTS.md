# Графики, таблицы и числовые доказательства

## Сначала вопрос

| Вопрос | Подходящая форма |
|---|---|
| Кто больше / меньше | Горизонтальные столбцы, прямые подписи |
| Как менялось во времени | Линия или столбцы по времени |
| Что изменилось между двумя моментами | Два числа, парные столбцы или простой dumbbell |
| Что выбрать по нескольким критериям | Небольшая таблица с выделенным решением |
| Какова структура целого | Полоса долей; круг только при простой структуре и ясных подписях |
| Как устроен процесс | Этапы или схема связей, а не псевдодиаграмма |

Типы не являются запретом на другие обоснованные решения. Не повторять дизайн графиков из отрицательных референсов. Строить заново из данных.

## Как выбрать рисунок графика для слайда

Рабочая редакция от 23.11.2026 для проверки на тестовых слайдах. Источник визуального направления — [15 референсов в Brand Core](https://www.figma.com/design/tmqVQnutHWMAoEWBCmvm67/01.-Brand-Core?node-id=2184-873). Цвет и типографику брать из Media Platforma.

До вёрстки запиши в плане слайда одну фразу: «Зрителю нужно увидеть ___; это видно по ___; поэтому выделяем ___». Например, один и тот же ряд месячных охватов даёт три разных макета. Для вопроса «когда был пик?» выдели одну точку и подпиши месяц. Для «как прошла кампания?» выдели интервал с известными датами. Для «сколько составил охват в конце периода?» поставь последнее значение крупно, а ряд оставь контекстом. Уникальный охват за весь период требует отдельного исходного показателя.

| Что есть на входе и что нужно увидеть | Как собрать композицию | Ориентир в Figma, ID внутри группы 2184 |
|---|---|---|
| Одно число без ряда. Важен масштаб результата | Число занимает отдельное поле. Рядом короткое название метрики, единица и период. При наличии разбивки вторым ярусом поставить график на всю ширину поля | 871, Strava |
| Длинный ряд. Важны максимум или конкретный отрезок | Собрать плотный ритм тонких вертикалей с общей базой. У максимума выделить один штрих, поставить точку и прямую подпись. Для интервала оставить одну акцентную группу и обозначить её границы датами | 856, профиль высоты; 868, Quantro |
| Несколько дискретных периодов. Важно сравнить величины | Поставить широкие столбцы или тонкие стержни с точкой на конце. Для задачи «последний период против обычного» приглушить историю, подписать последний период и вывести среднее тонкой линией, если оно известно | 849, недельные метрики; 871, месяцы |
| На каждый период известны минимум и максимум | Плавающий вертикальный отрезок соединяет два значения по общей шкале. Подписать границы выделенного диапазона. Внутреннюю точку добавлять только для известного третьего показателя | 846, Heart Rate; 854, чёрные интервалы |
| Несколько категорий. Важен порядок | Собрать столбцы на общей базе, поставить число у края каждого. Короткие названия можно вынести наверх в колонки, длинные — поставить слева от горизонтальных полос. При естественной последовательности сохранить её | 831, By company size |

Рядом крупно поставить точное значение и назвать базу. Для дробной доли обозначить округление графики или взять непрерывную полосу | 840, 67%; 843, пиктограммы |
| Несколько самостоятельных процентов. Нужно сопоставить результаты | На одной линии поставить равные по ширине шкалы 0–100. Под каждой — число и короткая расшифровка. При разных базах назвать каждую. Для частей одного целого собрать одну составную полосу с прямыми подписями | 837, Impact & Metrics; 831, By work environment |
| Несколько крупных величин. Важен скачок порядка | Разместить круги в отдельных колонках с общей нижней касательной, значения подписать прямо над ними. Площадь пропорциональна величине, радиус — квадратному корню. Для близких значений использовать столбцы | 834, розовая серия кругов |

| Несколько связанных KPI. Важна общая картина | Отдать главной метрике больше площади. Остальные собрать в один ряд с одинаковым порядком «название — число — мини-график». Общая шкала нужна для сопоставимых величин. Воронка требует последовательных этапов одной совокупности | 852, Insight; 859, Team revenue; 862, OxeliaMetrix; 865, Sales statistics |

### Что переносить на слайд

В референсе Strava крупное «67» задаёт вход в композицию, а подпись у июньской точки даёт вторую остановку взгляда. В Impact & Metrics ту же задачу решает повтор одинаковых шкал. Выбирай один из этих способов чтения под вывод. Размер ключевого числа и площадь графика проверяй одновременно на полном слайде. Для каждой подписи оставь место в пределах её колонки. Период и единица должны читаться вместе с числом.

Из интерфейсных примеров переноси ритм столбцов, соотношение числа и графика, выделение периода. Навигацию, фильтры, переключатели и кнопки опускай. На белом фоне мелкие подписи ставь почти чёрным; лаймовому маркеру добавь прямую подпись, чтобы он читался и при слабом контрасте проектора. На тёмном фоне держи самый яркий участок в точке вывода.

**Проверка тестового слайда.** Посмотри на миниатюру: какой элемент виден первым и отвечает ли он на вопрос слайда? Затем открой слайд в размере показа: можно ли назвать значение, единицу, период и базу сравнения? Сверь крайние значения, пропуски, длины, площади и число заполненных сегментов с исходной таблицей. Если без объяснения автора акцент непонятен, измени подпись или композицию до сдачи.

## Достоверность — обязательная проверка

- Есть источник, период, единицы, база сравнения. Расчёты проверены отдельно от оформления.
- Проценты различаются с процентными пунктами; среднее — с медианой; просмотры — с уникальным охватом.
- У столбцов количественная ось начинается с нуля. Разрыв шкалы не скрывается. Для линий диапазон может быть ограничен, но явно подписан и не преувеличивает изменение.
- Пропущенное значение не равно нулю. Не соединять линией отсутствие наблюдения без явного обоснования. Различать «не было в выдаче» и «нет данных».
- Для позиции в поиске объяснить, что №1 лучше; направление оси явно видно.
- Составные столбцы использовать только для складываемых частей одного целого. Не суммировать несовместимые метрики.
- При сравнении периодов учитывать их длительность. Если нужны продажи в день, вычислять по исходным данным, не по высоте картинки.
- Совпадение события и роста не доказывает причинность. Сохранять ограничения исследования.
- Не переносить числа из старых референсов в новую презентацию как актуальные данные.

## Визуальные правила

Один основной аналитический вопрос на слайд. Один крупный график предпочтительнее трёх маленьких. Если два графика нужны для одного вывода, проверить, что оба читаются без увеличения; иначе разделить.

Основной ряд/период выделять лаймом, сравнение — нейтральным цветом. Дополнительные цвета брать из брендовых токенов при реальной необходимости различить ряды. Цветовой смысл сохранять во всей презентации. Не полагаться только на цвет: использовать подписи, тип линий или расположение.

Подписывать данные рядом, когда это заменяет легенду. Убирать второстепенную сетку и повторяющиеся цифры. Не удалять важные экстремумы, периоды и единицы. Округление единообразное, точные значения доступны в таблице.

Не применять 3D-перспективу, металлические сектора, свечения, тени на столбцах, объёмные оси и декоративные маркеры. Metal 3D — метафора, а не точная визуализация чисел. Не выдавать декоративную круговую 3D-иконку за распределение данных.

Сохранять график редактируемым: нативный chart, SVG или векторные элементы с исходной таблицей. Растровый экспорт для просмотра допустим, но не заменяет данные и редактируемый исходник. Генератор изображений не использовать для аналитики.

## Нет исходных данных

Запросить таблицу или использовать только проверяемые числа, которые предоставлены явно. Не восстанавливать точный временной ряд по скриншоту на глаз. До получения данных допустим макет с обозначенными плейсхолдерами, но его нельзя выдавать как финальный отчёт.

## Переработка плохого примера

В 2166:3736 одновременно размещены видео, три маленьких разноцветных графика и три крупных результата. Разделить на «результат контента» и «динамику поиска», выбрать по одному доказательству, сохранить периоды и оговорки. Не ограничиваться перекрашиванием линий в зелёный.
