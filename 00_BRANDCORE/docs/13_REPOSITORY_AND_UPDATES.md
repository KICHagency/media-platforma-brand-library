# Репозиторий и обновление знаний

## Структура

README.md — вход для человека; AGENTS.md — вход для ассистента; docs — правила; prompts — исходные спецификации; tokens — цвета и типографика; registry — метки и ссылки на ассеты; templates — бриф и проверка; sources — происхождение правил и снимок текстов; LINKS.md — навигация.

Этот пакет можно положить в корень нового репозитория или в раздел Brand Core существующей библиотеки. Относительные ссылки рассчитаны на сохранение внутренней структуры. Публикация на GitHub в рамках подготовки документации не выполнялась.

## Что подключить позже

Экспорты PNG, SVG логотипов, исходные тайлы DIY и файлы шрифтов при наличии права на распространение. В registry/assets.json заменить local_file: null на реальный путь, указать параметры экспорта и статус проверки. Не ставить export_status=exported до появления файла.

Для фотографий отдельно хранить режим использования, для 3D — ракурс и прозрачность, для ASCII — фон, для логотипов — композицию и цветовой вариант. Роль задаёт graphic_roles.json; новые изображения наследуют её по типу.

## Подключение к Q&A

Для одной загрузки использовать MEDIA_PLATFORMA_BRAND_CORE_KNOWLEDGE_BASE.md. Для системы с тематическими файлами загрузить docs, AGENTS, prompts, tokens и registry. Не дублировать сборник и все составные файлы одновременно. Для визуальной генерации подключить изображения: текстовая база не передаёт референсы автоматически.

## Обновления

1. Зафиксировать новое указание владельца или изменение конкретного узла Figma.
2. Обновить профильный документ, соответствующий JSON/токен/роль и ссылку на источник.
3. Проверить, не конфликтует ли изменение с Core и соседними стилями.
4. Обновить Q&A, чек-лист, сборный MD и номер версии.
5. Записать изменение в CHANGELOG.md и проверить один характерный пример применения.

Не исправлять только объединённый MD: он производный. Не называть новую версию согласованной без фактического согласования владельцем. Не выдумывать точность по полям, где источник остаётся неопределённым.
